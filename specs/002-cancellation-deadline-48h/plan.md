## Summary

Change of feature 001 (FR-015, User Story 7): Guests may cancel online until 48 hours before check-in
(15:00 Europe/Zurich on the arrival date); reservations that exist before this change keep the 001 rule
(00:00 on the arrival date). Each reservation stores its rule as `cancellation_hours_before` (15 old,
48 new) and the deadline is computed from the arrival date, so a reception date change moves it
(research R1, R2). One `CancellationDeadline` type builds the deadline and its texts for the guest lookup
page, the reception grid, the cancel check and a new plain-text booking confirmation email, sent after the
booking is committed so a mail failure never undoes it (R3, R4).

## Technical Context

**Language/Version**: Java 25

**Primary Dependencies**: Spring Boot 4.1.1, Vaadin Flow 25.3.1, jOOQ, Flyway; new: `spring-boot-starter-mail`

**Storage**: H2 (file database in dev, in-memory in tests); one new column on `reservation` (V4)

**Testing**: JUnit with Spring Boot test, Vaadin Browserless (`HrsBrowserlessTest`), Playwright + Mopo
(`PlaywrightIT`), `@MockitoBean JavaMailSender` for the email

**Target Platform**: Server-side Vaadin web app, desktop and tablet browsers

**Project Type**: Web application (single Maven module, server-side UI)

**Performance Goals**: None new; ten-room hotel. Mail send has 5 s timeouts so a slow server cannot hang the
booking page longer than that.

**Constraints**: Deadlines in Europe/Zurich wall-clock time; existing reservations must keep the old rule;
mail failure must not affect the booking; other features keep their current "today" (Clock bean unchanged).

**Scale/Scope**: 1 migration, 1 new value type, 1 new mail service, 3 views changed, ~5 test classes changed
or added.
